### CQ11 — Which instrument was the biggest mover on each exchange?

- Requirement covered: CTE, window RANK PARTITION BY
- Tables used: 2 of the 7; nested/analytic construct: yes (template: ≥ 3 tables OR nested/analytic)
- Execution: **PASS** — psql exit 0, 2 row(s)
- Screenshot: status per query in docs/review2/SCREENSHOT_MATRIX.md
- Expected result (predicted before execution): 2 rows: BINANCE ETHUSDT -1.76 %; NSE RELIANCE -6.62 %.
- Explanation: Nested/analytic (2 tables): the CTE computes every instrument first-to-last % change, RANK() restarts per exchange (PARTITION BY exchange) and the outer filter keeps rank 1.

```sql
WITH moves AS (
    SELECT i.exchange, i.symbol,
           100 * ((array_agg(t.price ORDER BY t.observed_at DESC, t.tick_id DESC))[1]
                  - (array_agg(t.price ORDER BY t.observed_at, t.tick_id))[1])
               / (array_agg(t.price ORDER BY t.observed_at, t.tick_id))[1] AS change_pct
    FROM price_ticks t
    JOIN instruments i ON i.instrument_id = t.instrument_id
    GROUP BY i.exchange, i.symbol
)
SELECT exchange, symbol, round(change_pct, 2) AS change_pct, move_rank
FROM (SELECT m.*,
             rank() OVER (PARTITION BY m.exchange ORDER BY abs(m.change_pct) DESC) AS move_rank
      FROM moves m) AS x
WHERE move_rank = 1
ORDER BY exchange;
```

### CQ12 — Which watchlist performed best (equal-weighted average % change of its instruments)?

- Requirement covered: 5 tables, CTE, LEFT JOIN
- Tables used: 5 of the 7; nested/analytic construct: yes (template: ≥ 3 tables OR nested/analytic)
- Execution: **PASS** — psql exit 0, 5 row(s)
- Screenshot: status per query in docs/review2/SCREENSHOT_MATRIX.md
- Expected result (predicted before execution): 5 rows: priya Tech 2 instruments / 2 priced / -0.02; arjun Crypto 2 / 2 / -0.40; kavya Main 3 / 3 / -1.32; arjun Long Term 3 / 2 / -4.18 (HDFCBANK has no ticks); priya Auto 1 / 0 / null.
- Explanation: The CTE gives each instrument % move; LEFT JOIN keeps watchlist items without prices, avg() ignores their NULLs, and count(m.change_pct) shows how many instruments were actually averaged.

```sql
WITH moves AS (
    SELECT t.instrument_id,
           100 * ((array_agg(t.price ORDER BY t.observed_at DESC, t.tick_id DESC))[1]
                  - (array_agg(t.price ORDER BY t.observed_at, t.tick_id))[1])
               / (array_agg(t.price ORDER BY t.observed_at, t.tick_id))[1] AS change_pct
    FROM price_ticks t
    GROUP BY t.instrument_id
)
SELECT u.username, w.name AS watchlist,
       count(wi.instrument_id)     AS instruments,
       count(m.change_pct)         AS instruments_with_prices,
       round(avg(m.change_pct), 2) AS avg_change_pct
FROM watchlists w
JOIN users u            ON u.user_id = w.user_id
JOIN watchlist_items wi ON wi.watchlist_id = w.watchlist_id
LEFT JOIN moves m       ON m.instrument_id = wi.instrument_id
GROUP BY u.username, w.name
ORDER BY avg_change_pct DESC NULLS LAST, u.username, w.name;
```
